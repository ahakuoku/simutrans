# 連動盤ブリッジ プロトコル（試作版）

ゲームは `127.0.0.1` だけで TCP 接続を受け付ける。同じポートで次の 2 種類を受け付ける。

- **HTTP**（Web 盤）: ブラウザで `http://127.0.0.1:13360/` を開くと盤の画面が出る。API は下の「HTTP API」。
- **行単位プロトコル**（コンソール盤・テスト・中継プログラム）: 1 行 1 メッセージ（UTF-8、改行区切り）。

ゲーム → 盤のメッセージはすべて JSON。

## ポート

- 既定は **13360**（設定なしで有効）。専用サーバ（`-server`）のときだけ、明示的に設定しない限り無効。
- 変更・無効化: ユーザーディレクトリに `interlocking.tab` を置き、`port=13361` のように書く（`port=0` で無効）。
- 環境変数 `TID_IL_PORT` があればそれを優先する。

## HTTP API（Web 盤）

| メソッド・パス | 内容 |
|---|---|
| `GET /` | 盤の画面（`index.html`）。下の「盤のファイル」から読む |
| `GET /api/status` | 行単位の `status` と同じ |
| `GET /api/events?since=N` | 通番 N より後のイベント。`{"last":M,"events":[...]}` |
| `GET /api/tracks?x1=&y1=&x2=&y2=` | 範囲内の線路（配線略図用、下記） |
| `GET /api/halts` | 鉄道のホームがある駅の一覧（`id`、`name`、`owner`、`tiles`） |
| `GET /api/info` | マップの大きさ、操作中のプレイヤー、会社の一覧（`players`: `nr`、`name`） |
| `POST /api/cmd` | 本文に連動装置のコマンド（下表）。**ヘッダ `X-IL-Panel: 1` が必須** |

安全のため、`Host` ヘッダが `127.0.0.1:ポート` / `localhost:ポート` 以外の要求は拒否する（DNS リバインディング対策）。
また、`X-IL-Panel` ヘッダのない POST は拒否する（ほかの Web サイトからの勝手な操作を防ぐ）。

### `/api/tracks` の各タイル

`{"p":[x,y,z],"r":つながっている方向,"m":通れる方向,"h":駅ID,"d":1(車庫),"c":予約している列車ID,"s":{"dir","aspect","o":所属会社,"name","ch":1(選択信号),"g":連結誘導(選択信号のとき 0/1)}}`
方向はビットで 1 = 北、2 = 東、4 = 南、8 = 西。`m` は片方向の信号などで通れない方向を除いたもの。
`convoys` に列車 ID → 列車名の対応が入る。

### 盤のファイル

次の順に探し、最初に `index.html` が見つかったフォルダを使う。

1. 環境変数 `TID_IL_PANEL_DIR`
2. Simutrans のフォルダ（データディレクトリ）の `interlocking_panel/`
3. ユーザーディレクトリの `interlocking_panel/`
4. データディレクトリの `../interlocking/panel/`（ソースからビルドしてそのまま動かす場合）

## 盤 → ゲーム

| リクエスト | 内容 |
|---|---|
| `cmd <コマンド>` | 連動装置のコマンドを実行する（下表）。結果は `result` イベントで返る |
| `status` | 全連動駅・全進路の状態を返す |
| `signals x1 y1 x2 y2` | 四角形の範囲にある信号の一覧を返す（設定画面用） |
| `tracks x1 y1 x2 y2` | `/api/tracks` と同じ |
| `halts` | `/api/halts` と同じ |
| `ping` | `pong` を返す |

`cmd` は、ネットワークゲームではサーバを経由して全員のゲームで同じタイミングで実行される。
盤はボタンを押したら `result` が返るまで「扱い中」と表示する。

### 連動装置のコマンド（`cmd` の後ろ）

| コマンド | 書式 | 内容 |
|---|---|---|
| 駅を作る | `st_new,<名前>` | 操作したプレイヤーが所有者になる |
| 駅を消す | `st_del,<駅ID>` | その駅の進路も消える |
| モード切替 | `st_mode,<駅ID>,<0/1>` | 0 = 自動、1 = 扱者。自動に戻すと「設定済み」の進路は取り消す |
| てこ扱い信号の登録 | `sig_add,<駅ID>,x,y,z` | 線路の信号がある座標 |
| 登録の解除 | `sig_del,<駅ID>,x,y,z` | |
| 仮想出発・入換信号の登録 | `dep_add,<駅ID>,x,y,z[,D/S]` | 番線（ホーム）または線路（ポイント・信号・ホーム・車庫で区切られた範囲。留置線・引上線）を出発点にする。x,y,z は線路のどこか（両端に線路が続くときは、列車が出ていく側の端）。D = 出発信号、S = 入換信号（省略時はホームなら D、それ以外は S）。両端から出られる線路は、端ごとに 1 つずつ置ける |
| 仮想出発・入換信号の解除 | `dep_del,<駅ID>,x,y,z` | 信号を置いた端、またはその線路のどこか（信号が 1 つだけのとき） |
| 留置線として扱う駅 | `st_sid,<駅ID>,x:y:z;x:y:z` | 区域内のほかの駅（駅属性の留置線）。各駅のタイルを 1 つずつ。空で解除 |
| 進路の定義 | `rt_def,<駅ID>,sx,sy,sz,ex,ey,ez,<名前>` | 始点（登録済みの信号、または仮想出発信号の端）から着点まで線路をたどって経路を決める |
| 進路の削除 | `rt_del,<進路ID>` | |
| 進路の名前 | `rt_name,<進路ID>,<名前>` | 名前に `,` を含めてよい |
| その場で進路を引く | `set_path,<駅ID>,x:y:z;x:y:z;...,<名前>` | 盤の「信号てこ→着点ボタン」で使う。経路のタイル列を直接指定し、線路のつながりと進む向きを検証してから設定する。解除されると自動で消える（`temp`） |
| 名称の変更 | `name_set,<駅ID>,x,y,z,<名前>` | 信号・番線・出口・ポイントなどの名前。空にすると自動の名前に戻る |
| 転てつてこ | `pt_set,<駅ID>,x:y:z/<値>/a-b.c-d;...` | ポイントの向きを固定する。値は表示用（`N` 定位、`R` 反位、`a,b` その他）、`a-b` は通してよい方向の組（方向ビット）。値を空にすると自動。複数のポイント（双動）は 1 回でまとめて設定し、1 つでも不正なら全体を拒否。進路が通っている・在線中のポイントは変えられない |
| 進路の登録（経路指定） | `rt_path,<駅ID>,x:y:z;x:y:z;...,<名前>` | `set_path` と同じタイル列で、登録済みの進路（ショートカット）を作る。盤の「進路を自動作成」が使う |
| 駅の設定 | `st_cfg,<駅ID>,<種類>,<向き>,<時素本線>,<時素入換>,<転換時間>` | 種類 0 = 電子、1 = 継電。向き = 継電の盤の回転（0〜3、時計回りに 90° 単位、全員共通）。時間は秒（ゲーム内時間、通常速度）。種類の変更は進路がすべて解除されているときだけ。所有会社だけ |
| 操作できる会社 | `st_ops,<駅ID>,<番号.番号...>` | 所有会社のほかに操作できる会社。空で所有会社だけ。所有会社だけが変更できる |
| 信号てこをまとめる（継電） | `lv_pair,<駅ID>,lx,ly,lz,rx,ry,rz` | 1 本のてこで、左に倒すと l、右に倒すと r の信号を扱う。l・r の側は固定（`sl_turn` で反対側は拒否）。同時に倒せるのは片側だけ |
| まとめの解除 | `lv_unpair,<駅ID>,x,y,z` | |
| てこを倒す向き（継電） | `lv_side,<駅ID>,x,y,z,<L/R/A>` | 盤で自動に決める向きを手で変える（A = 自動に戻す）。全員共通 |
| 一斉停止てこ | `st_stop,<駅ID>,<0/1>` | 1 の間、その駅の設定済みの進路の信号は進行にならない |
| 入換てこ | `lv_shunt,<駅ID>,x,y,z,<W/G/P/N>` | 信号・出発点に入換用のてこを付ける（W = 白・入換信号機、G = 緑・入換標識、P = ピンク・誘導信号、N = 外す） |
| 入換てこで進路を引く（電子） | `set_path_s,<駅ID>,x:y:z;...,<名前>` | `set_path` と同じ。その始点の入換てこで引く（継電の盤では、倒したてこで決まる） |
| 信号てこ（継電） | `sl_turn,<駅ID>,x,y,z,<L/R/N>[,S]` | L・R = 開通方向にひねる（盤の上の左右）、N = 定位に戻す。戻すと設定済みの進路は取り消し（列車が接近中なら時素） |
| 進路を引く | `set,<進路ID>` | 扱者モードのときだけ。継電の駅では使えない |
| 進路を戻す | `cancel,<進路ID>` | 列車が進入する前だけ |

### 継電連動（`st_cfg` の種類 1）

- 進路（`set_path`）は、その始点の信号てこを `sl_turn` でひねってからでないと引けない。1 回ひねるごとに 1 本。
  着点待ち（ひねったが進路をまだ引いていない）のてこは、駅ごとに 1 本だけ。`,S` を付けると、その始点の入換てこ。入換てこで引いた進路は入換進路（`shunt`、時素は入換の秒数）。
- 同じ番線・留置線に列車が止まっていて、その手前で終わる進路は、緑（入換標識）かピンク（誘導信号）の入換てこでだけ引ける（電子・継電とも）。
  白と緑の入換てこで引いた進路は入換進路、ピンクは列車の進路。
- 止まっている列車の後ろで終わる進路は、進入する列車全体がその番線・留置線に収まるときだけ進入させる。収まらないときは
  信号を停止のままにして `too_long` イベント（`id`、`room`・`need`＝空いている／必要なマス数、`convoy`）を出す。
  列車が通過して進路が解けても、てこは反位のまま（`used`）。次の進路の前に `N` に戻す。
- 進路を引くと、向きの違うポイントは転換時間のあいだ動き、すべて転換を終えてから信号が進行になる（`waiting`）。
- 列車が接近中（信号の手前の区間を列車が予約している、または仮想出発・入換信号の線路に列車がいる）に進路を取り消すと、
  進路は `releasing` になり、時素（本線・入換の秒数）がたってから解ける。その間は鎖錠されたまま。
- 転てつてこ（`pt_set`）で固定したポイントも、向きが変わるときは転換時間がかかる。

### 通過列車

仮想出発信号のある番線で終わる進路に入ろうとする列車が、その番線（同じ駅）に止まらないときは、
その番線の出発点から出る進路も設定されているときだけ進入させ、両方の進路を通る経路にする（両方 `occupied` になる）。
出発の進路がなければ場内信号で待つ。進路は、ほかの進路の終わりのタイルから始まってよい（敵対としない）。

### セーブデータ

マーカー `0xA6` のあとに長さ付きのデータのかたまり（`il_blob.h`）。駅・進路などは長さ付きの区切りで、知らない部分は読み飛ばす。
旧形式（マーカー `0xA5`、版数 1〜9）も読める。

### 進路を引くときの判定（`set`）

- 同じ信号から出る別の進路が設定されていないこと
- 設定済みのほかの進路とタイルを共有していないこと（敵対進路）
- 進路の線路（信号のタイルの次から着点まで）がどの列車にも予約されていないこと
- 固定されたポイント（`pt_set`）を通る場合、その向きに合っていること

## ゲーム → 盤（イベント）

| type | 内容 |
|---|---|
| `result` | コマンドの結果。`command`、`ok`、失敗時は `error` |
| `station` | 駅が作られた。`id`、`name` |
| `mode` | モードが変わった。`station`、`manual` |
| `route_defined` | 進路が定義された。`id`、`station`、`tiles`（タイル数） |
| `route` | 進路の状態が変わった。`id`、`station`、`state`（`idle` / `set` / `occupied` / `releasing`）、`convoy`（進入した列車名） |
| `wrong_route` | 設定された進路の先から列車の目的地へ行けない。`id`、`convoy` |
| `reset` / `rotated` | マップの読み込み・作り直し／回転。盤は `status` を取り直す |

### `status` の例

```json
{"type":"status",
 "stations":[{"id":1,"name":"A station","owner":0,"manual":true,
              "signals":[{"pos":[3,5,0],"aspect":"red"}]}],
 "routes":[{"id":2,"station":1,"name":"S1-1","state":"idle","start":[3,5,0],"end":[8,5,0],
            "occupied":[1,0,0,0,0,0],"tiles":[[3,5,0],[4,5,0],[5,5,0],[6,5,0],[7,5,0],[8,5,0]]}]}
```

`occupied` は進路の各タイルが列車に予約されているか（1 = 在線または予約中）。
信号の `train` は、その信号のタイルを押さえている列車（信号で待っている列車）。盤の接近表示に使う。
駅の `kind`（`electronic` / `relay`）、`rot`、`t_approach`・`t_shunt`・`t_throw`（秒）、`all_stop`、`operators`（会社番号）、
`siding_halts`（留置線として扱う駅のタイル）、`pairs`（まとめた信号てこ `[[左],[右]]`）、`slevers`（ひねってある信号てこ: `pos`、`side`、`used`）、`points`（継電: ポイントの向き `pair` と転換の残り秒数 `moving`）。
進路の `waiting`（転換中・一斉停止で信号が進行にならない）、`release_in`（時素の残り秒数）。
駅の `labels` は盤で付けた名前（`pos`、`name`）。駅の `levers` は固定されたポイント（`pos`、`value`、`pairs`）。進路の `temp` は「その場で引いた進路」（解除されると消える）。
駅の `departures` は仮想出発信号: `pos`（出発点＝進路の始点）、`tiles`（番線のタイル）、`train`（番線にいる列車）、`waiting`（発車待ちか）。
ホームのない線路のもの（仮想入換信号）は `"shunt":true` が付く。

| リクエスト | 内容 |
|---|---|
