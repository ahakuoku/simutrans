# 連動盤ブリッジ プロトコル（試作版）

ゲームは `127.0.0.1` だけで TCP 接続を受け付ける。同じポートで次の 2 種類を受け付ける。

- **HTTP**（Web 盤）: ブラウザで `http://127.0.0.1:13360/` を開くと盤の画面が出る。API は下の「HTTP API」。
- **行単位プロトコル**（コンソール盤・テスト・中継プログラム）: 1 行 1 メッセージ（UTF-8、改行区切り）。

ゲーム → 盤のメッセージはすべて JSON。

## ポート

- 既定は **13360**（設定なしで有効）。専用サーバ（`-server`）のときだけ、明示的に設定しない限り無効。
- 変更・無効化: ユーザーディレクトリに `interlocking.tab` を置き、`port=13361` のように書く（`port=0` で無効）。
- 環境変数 `TID_IL_PORT` があればそれを優先する。

## HTTP API（Web 盤）

| メソッド・パス | 内容 |
|---|---|
| `GET /` | 盤の画面（`index.html`）。下の「盤のファイル」から読む |
| `GET /api/status` | 行単位の `status` と同じ |
| `GET /api/events?since=N` | 通番 N より後のイベント。`{"last":M,"events":[...]}` |
| `GET /api/tracks?x1=&y1=&x2=&y2=` | 範囲内の線路（配線略図用、下記） |
| `GET /api/halts` | 鉄道のホームがある駅の一覧（`id`、`name`、`owner`、`tiles`） |
| `GET /api/info` | マップの大きさ、操作中のプレイヤー、会社の一覧（`players`: `nr`、`name`） |
| `POST /api/cmd` | 本文に連動装置のコマンド（下表）。**ヘッダ `X-IL-Panel: 1` が必須** |

安全のため、`Host` ヘッダが `127.0.0.1:ポート` / `localhost:ポート` 以外の要求は拒否する（DNS リバインディング対策）。
また、`X-IL-Panel` ヘッダのない POST は拒否する（ほかの Web サイトからの勝手な操作を防ぐ）。

### `/api/tracks` の各タイル

`{"p":[x,y,z],"r":つながっている方向,"m":通れる方向,"h":駅ID,"d":1(車庫),"c":予約している列車ID,"s":{"dir","aspect","o":所属会社,"name"}}`
方向はビットで 1 = 北、2 = 東、4 = 南、8 = 西。`m` は片方向の信号などで通れない方向を除いたもの。
`convoys` に列車 ID → 列車名の対応が入る。

### 盤のファイル

次の順に探し、最初に `index.html` が見つかったフォルダを使う。

1. 環境変数 `TID_IL_PANEL_DIR`
2. Simutrans のフォルダ（データディレクトリ）の `interlocking_panel/`
3. ユーザーディレクトリの `interlocking_panel/`
4. データディレクトリの `../interlocking/panel/`（ソースからビルドしてそのまま動かす場合）

## 盤 → ゲーム

| リクエスト | 内容 |
|---|---|
| `cmd <コマンド>` | 連動装置のコマンドを実行する（下表）。結果は `result` イベントで返る |
| `status` | 全連動駅・全進路の状態を返す |
| `signals x1 y1 x2 y2` | 四角形の範囲にある信号の一覧を返す（設定画面用） |
| `tracks x1 y1 x2 y2` | `/api/tracks` と同じ |
| `halts` | `/api/halts` と同じ |
| `ping` | `pong` を返す |

`cmd` は、ネットワークゲームではサーバを経由して全員のゲームで同じタイミングで実行される。
盤はボタンを押したら `result` が返るまで「扱い中」と表示する。

### 連動装置のコマンド（`cmd` の後ろ）

| コマンド | 書式 | 内容 |
|---|---|---|
| 駅を作る | `st_new,<名前>` | 操作したプレイヤーが所有者になる |
| 駅を消す | `st_del,<駅ID>` | その駅の進路も消える |
| モード切替 | `st_mode,<駅ID>,<0/1>` | 0 = 自動、1 = 扱者。自動に戻すと「設定済み」の進路は取り消す |
| てこ扱い信号の登録 | `sig_add,<駅ID>,x,y,z` | 線路の信号がある座標 |
| 登録の解除 | `sig_del,<駅ID>,x,y,z` | |
| 仮想出発信号の登録 | `dep_add,<駅ID>,x,y,z` | ホームの番線を出発点にする。x,y,z は番線のどこか（両端に線路が続く番線では、列車が出ていく側の端） |
| 仮想出発信号の解除 | `dep_del,<駅ID>,x,y,z` | |
| 進路の定義 | `rt_def,<駅ID>,sx,sy,sz,ex,ey,ez,<名前>` | 始点（登録済みの信号、または仮想出発信号の端）から着点まで線路をたどって経路を決める |
| 進路の削除 | `rt_del,<進路ID>` | |
| その場で進路を引く | `set_path,<駅ID>,x:y:z;x:y:z;...,<名前>` | 盤の「信号てこ→着点ボタン」で使う。経路のタイル列を直接指定し、線路のつながりと進む向きを検証してから設定する。解除されると自動で消える（`temp`） |
| 名称の変更 | `name_set,<駅ID>,x,y,z,<名前>` | 信号・番線・出口・ポイントなどの名前。空にすると自動の名前に戻る |
| 転てつてこ | `pt_set,<駅ID>,x:y:z/<値>/a-b.c-d;...` | ポイントの向きを固定する。値は表示用（`N` 定位、`R` 反位、`a,b` その他）、`a-b` は通してよい方向の組（方向ビット）。値を空にすると自動。複数のポイント（双動）は 1 回でまとめて設定し、1 つでも不正なら全体を拒否。進路が通っている・在線中のポイントは変えられない |
| 進路を引く | `set,<進路ID>` | 扱者モードのときだけ |
| 進路を戻す | `cancel,<進路ID>` | 列車が進入する前だけ |

### 進路を引くときの判定（`set`）

- 同じ信号から出る別の進路が設定されていないこと
- 設定済みのほかの進路とタイルを共有していないこと（敵対進路）
- 進路の線路（信号のタイルの次から着点まで）がどの列車にも予約されていないこと
- 固定されたポイント（`pt_set`）を通る場合、その向きに合っていること

## ゲーム → 盤（イベント）

| type | 内容 |
|---|---|
| `result` | コマンドの結果。`command`、`ok`、失敗時は `error` |
| `station` | 駅が作られた。`id`、`name` |
| `mode` | モードが変わった。`station`、`manual` |
| `route_defined` | 進路が定義された。`id`、`station`、`tiles`（タイル数） |
| `route` | 進路の状態が変わった。`id`、`station`、`state`（`idle` / `set` / `occupied`）、`convoy`（進入した列車名） |
| `wrong_route` | 設定された進路の先から列車の目的地へ行けない。`id`、`convoy` |
| `reset` / `rotated` | マップの読み込み・作り直し／回転。盤は `status` を取り直す |

### `status` の例

```json
{"type":"status",
 "stations":[{"id":1,"name":"A station","owner":0,"manual":true,
              "signals":[{"pos":[3,5,0],"aspect":"red"}]}],
 "routes":[{"id":2,"station":1,"name":"S1-1","state":"idle","start":[3,5,0],"end":[8,5,0],
            "occupied":[1,0,0,0,0,0],"tiles":[[3,5,0],[4,5,0],[5,5,0],[6,5,0],[7,5,0],[8,5,0]]}]}
```

`occupied` は進路の各タイルが列車に予約されているか（1 = 在線または予約中）。
信号の `train` は、その信号のタイルを押さえている列車（信号で待っている列車）。盤の接近表示に使う。
駅の `labels` は盤で付けた名前（`pos`、`name`）。駅の `levers` は固定されたポイント（`pos`、`value`、`pairs`）。進路の `temp` は「その場で引いた進路」（解除されると消える）。
駅の `departures` は仮想出発信号: `pos`（出発点＝進路の始点）、`tiles`（番線のタイル）、`train`（番線にいる列車）、`waiting`（発車待ちか）。

## テスト専用（環境変数 `TID_IL_DEBUG` を指定したときだけ）

| リクエスト | 内容 |
|---|---|
| `debug_tool <simple tool 番号> <パラメータ>` | 任意の simple tool を実行する（GUI のクリックと同じくネットワーク同期される） |
| `debug_convoys` | 全列車の ID・位置・状態・速度 |
| `debug_save <名前>` | `save/<名前>.sve` に保存する |
